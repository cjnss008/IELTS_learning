# IELTS Learning · 雅思 52 篇学习包

当前版本：**0.0.10**（见 [VERSION](VERSION)）。

项目围绕 52 篇英语文章提供离线阅读、英式音频跟读、词汇练习和自测。前 40 篇来自原学习材料，第 41—52 篇为新编补充；学习记录保存在当前浏览器本机。

## 学习目标与每日计划

面向零基础自学者，按 52 周、每天 6 小时学习雅思 Academic，目标为听说读写**各 6.5**，以各 7.0 作为训练参考。时长与打卡不等于能力保证，使用阶段测评、作品评阅和薄弱项补强持续校正。

打开 [每日学习计划.html](每日学习计划.html) 设置开课日期。每天七项任务共 360 分钟，每周 42 小时，全年 2184 小时；前 8 周先补基础。计划记录分钟、完成数量和成果，每 4 周测评一次，补强包含在 6 小时内。支持独立备份恢复。详见 [计划说明](每日学习计划说明.md)。

现有 52 篇短文是补充阅读，尚不能替代完整的分级课程、雅思真题或合格教师评阅。

## 开始学习

1. 保持整个文件夹结构完整，用浏览器打开 **[开始学习.html](开始学习.html)**。
2. 在左侧选择课文，按需使用正常语速、慢速段落跟读、中英对照、单词释义和默写练习。
3. 定期使用页面的“导出学习记录”功能备份进度；换浏览器、换设备或清理浏览器数据后，记录不会自动同步。

课文和音频可直接离线使用。AI 功能需要 Node.js 22 或更新版本及联网。双击 **启动学习.cmd**，打开 `http://127.0.0.1:8765/`，进入 [AI 设置](AI设置.html)，填写 API 基础地址和密钥，确认连接后选择接口实际提供的模型。默认偏好 `deepseek-flash`；模型可用性以服务商返回为准。

密钥仅存在本地服务内存，关服务即清除，不保存进浏览器、项目文件或 Git。配置地址、模型和秘密必须分开处理；切勿提交凭据。验证按钮会发送极短请求，可能产生 API 费用。页面中的外部词典等链接需要联网。详细操作见 [使用说明.md](使用说明.md)。

## 零基础起步

[基础入门](基础入门.html) 提供与前 8 周对应的 8 个单元、24 段中文讲解、英文例句与小对话、64 道练习及解析。从字母名称与发音的区别、自我介绍、be 动词起步，逐步练习数量、习惯、能力、位置、进行时与过去/计划。支持主动点击合成朗读；没有英语声音时保留文字练习。它是入门桥梁，不能单独填满每天 6 小时，仍需适级听读材料与反馈。

## 强化练习

每篇增加“语法精练”：原文对应的 3 个重点、中文拆句与常见错因，每点 2 道练习及解析，共 156 点 / 312 题。答案仅代表本题反馈，不替代写作或口语中的实际运用。

课文标题下的“逐句听写”入口使用现有慢速音频的词级时间点，逐句播放后自动停止；支持提示、答案差异和错句重练。文字准确率只用于听写练习，不换算雅思成绩。原有练习与记录键保留。

[生词复习](生词复习.html) 提供原句词卡、先到期后新学、每日全局最多 20 张新词、四种回忆评分及 Anki TSV 导出。采用可解释的固定间隔规则，最长 180 天，不是 FSRS。零基础阶段先从简单词开始，原课文的 360 张词卡供后续使用。

在每课“原句生词本”保存词组、自己的释义与上下文；刷新复习页即可加入个人词卡队列。听写核对答案后再修改会标为使用提示，可选择“重新闭卷尝试”安排延迟复测。

[口语练习](口语练习.html) 提供每课选句、短录音回放下载与原创 Part 1–3 自由表达题。可另配 Azure Speech 资源进行短句发音诊断；不配置也可回听。点击发送才上传录音和参考句，密钥只存本地服务内存；0–100 分不是 IELTS Band。详见 [语音评测说明](语音评测说明.md)。

[写作与 AI 辅导](写作与AI辅导.html) 包含 6 道有明确模拟数据的 Academic Task 1 表格题、6 道 Task 2 议论文题、计时、词数、分题草稿和修改前后对照；也支持语法解释与口语回答文字反馈。题目和草稿在点击发送时才交给已选 API，AI 建议需要复核，文字反馈不评发音。无 API 时仍可离线写作。

### 在其他位置获取完整副本

先安装 Git 和 Git LFS，再运行：

```powershell
git lfs install
git clone https://github.com/cjnss008/IELTS_learning.git
cd IELTS_learning
git lfs pull
```

已有 NAS 工作目录已初始化，无需再次克隆。EPUB 约 160 MiB，超过 GitHub 普通 Git 文件的 100 MiB 上限，因此通过 [Git LFS](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github) 保存；未使用 Git LFS 的副本可能只拿到指针文件。

## 版本与 GitHub 同步规则

1. 初始版本为 **0.0.0**，首次上传并建立标签 **v0.0.0**。
2. 每完成一次可独立说明的功能修改或修复，将末位版本号加 1：`0.0.1 → 0.0.2 → …`。版本号采用三段数字记录，本阶段不自动在 10 时进位。
3. 每次完成修改，同步更新 `VERSION`、本 README 的当前版本及 [CHANGELOG.md](CHANGELOG.md)，完成必要检查后提交到本地 Git。
4. **每累计 10 个小版本，向 GitHub 推送一次**：同步点依次为 **0.0.10、0.0.20、0.0.30**，依此类推。推送时包含这批本地提交，并建立对应的 `v0.0.10` 等标签。
5. 未到同步点时保留本地提交；用户明确要求提前上传时，按当次要求执行。大版本调整另行约定。

例如，到达 0.0.10 且验证完成后执行：

```powershell
git tag -a v0.0.10 -m "Release 0.0.10"
git push origin main
git push origin v0.0.10
```
